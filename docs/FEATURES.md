# 卡牌特征：信息完整度、维度与可训练性

推荐下一版采用 **20×6 卡牌区域 one-hot + 60 维上下文 = 180 维当前快照，配合 64 维 GRU 处理完整玩家可见事件历史**。当前这次算法对比继续使用 v2 的 465 维，以免同时改变算法和表征。180+GRU 是基于代码审计的推荐，尚未经过同预算表征消融，不能称作已经实证最优。

## 现有 465 维到底包含什么

实际编码源是 `native/src/features.rs`，不是已停用的 `feacture.py`。原生输入只接收 `PlayerObservation`；第一阶段不读取对手隐藏手牌或牌堆顺序。当前固定规则第二阶段会公开可推导的对手手牌。牌只有 20 张：4 花色 × J/Q/K/10/A，牌点为 2/3/4/10/11。动作是 20 张牌 + 4 报婚 + 4 换将，共 28 个固定索引。

| v2 索引（右边界不含） | 维度 | 实际内容 | 审计结论 |
| --- | ---: | --- | --- |
| 0–13 | 13 | 双方直接/待兑现分数、牌堆长度、将牌花色、阶段、是否领出 | 有用；二元量不必各占两个 one-hot 槽 |
| 13–133 | 120 | 每张牌六类区域 | 高信息密度且维度小，建议保留 |
| 133–243 | 110 | 最近五条记录，每条领出动作与相对赢家 | 没有跟牌动作；换将记录变成全零；不足以保留完整可见历史 |
| 243–443 | 200 | 最多十个合法动作，每个用 20 维描述，不足补零 | 动作集合已可由 28 维 mask 表达；排列引入无战略意义的顺序依赖 |
| 443–445 | 2 | 可换将、手中有将牌 | 可从 mask、手牌与将牌推导 |
| 445–465 | 20 | 当前领先动作 | 跟牌决策必需，应单独保留 |

每个动作描述包含 `3 类型 + 13 rank + 4 suit`。但只有五种 rank，13 个 rank 槽里 8 个永远不用。五个历史动作、十个合法动作和一个当前动作共 16 个槽，**至少 16×8=128 维在结构上永远为零**。这是代码可证明的冗余，不是由有限采样猜测。

另外，历史和当前领先动作不会是换将，因此还有类型位常零。采样中可能发现更多零/常量维，但不能仅凭几千局删掉罕见报婚或特殊合法动作。审计命令区分“结构性无效”和“本次没观察到”：

```powershell
.venv/Scripts/python.exe -m nfsp feature-audit --games 4096 --output runs/feature_audit
```

本机 4,096 局随机合法自博弈共采集 65,308 个决策观测：历史块 45 维常零、合法动作块 127 维常零/128 维常量、当前动作块 9 维常零。总计 181 维采样常零、182 维采样常量。120 维卡牌区域块所有维度都出现变化。

## 哪些信息一定要保留

单张牌的六个区域是：未知、公开底部将牌、对手已赢得的牌、已知仍在对手手中的牌、我已赢得的牌、我的手牌。固定 card ID 位置同时标识花色与点数，不需要再为每张牌重复 4+5 维身份编码。

“未知”不代表“在牌堆”，也不代表“在对手手中”。第一阶段必须保留这种不确定性。报婚透露的牌、换将取得的公开将牌、当前领出的牌都要按**当时可见信息**表达，不能从真实状态补全。当前领先牌必须独立编码，因为区域向量不一定能完整区分“对手持有”和“当前桌面上的领先牌”。

直接分数和待兑现婚分不能合并：同样 40 点，其中一部分待赢一墩后兑现，会改变局势。牌堆长度、阶段、谁领出、当前领先牌决定跟牌限制与牌权价值。训练胜负 +1/-1 和评估游戏点差也不能混为一项：对未获分对手赢牌可能获得 3 游戏点，而赢率目标并不会主动最大化这个收益。

比维度更关键的是记忆。当前赢牌集合只告诉你哪些牌已经离场，不告诉你谁在什么局势下主动出了哪张牌。五条历史还丢掉跟牌牌张、较早事件和换将顺序；这些信息可能帮助推断对手策略及剩余手牌分布。**缩小向量不能自动修复部分可观测性；换成更大的 MLP 也不能恢复被编码器丢弃的事件。**

## 推荐的 180 维快照

| 组成 | 维度 | 具体定义 |
| --- | ---: | --- |
| 卡牌区域 | 120 | 固定 20 个 card ID，每个六类 one-hot |
| 分数与牌堆 | 5 | 我/对手的直接及待兑现分数各一维；talon 长度一维 |
| 将牌花色 | 4 | 四类 one-hot |
| 阶段与领出 | 2 | phase2、am_i_leader 两个二元量 |
| 当前领先动作 | 21 | 20 张牌 one-hot + marriage 标志；无领先动作时全零，报婚对应实际领出的 Queen |
| 合法动作 | 28 | 固定动作索引 multi-hot，同时独立用于输出 logits 的硬掩码 |
| **合计** | **180** | 120+5+4+2+21+28 |

不要把区域类别编码成 0…5 的单一浮点数：这会引入“手牌比已知对手牌大”等虚假序关系。也不要把五张手牌排序后拼接成五个槽，再让模型重新学习集合的置换不变性。20×6 在这副小牌上足够便宜，且容易审计隐藏信息泄漏。

28 维合法 mask 同时进入状态并约束输出是有意的：这有利于价值网络识别可选行动；状态中不再存 200 维有顺序的合法动作描述。全局归一化保持固定且可解释；`score/66` 可能略超过 1，因为终局附近/婚分可以越过获胜阈值，不应未经分析强行截断。

180 维只保留当前快照，直接用它替代 465 维并称“无损”是错误的：它丢掉了原有五条有限历史。过渡消融可保留原 110 维历史，形成 **290 维** 版本，先测去冗余的影响；再把历史换成完整事件记忆。290 维保留了已有历史抽象的语义，但不保留无意义的合法动作排列。

## 如何补全记忆又不展开组合空间

推荐用一个共享的 64 hidden GRU，按玩家视角处理**所有该玩家可见的新事件**，再将记忆与当前快照送入策略/价值头。[DRQN 原始论文](https://arxiv.org/abs/1507.06527) 提供了在部分可观测任务中使用递归记忆的基础证据；这里选择 GRU/64 是针对小牌组和短局的工程推断，不是该论文对 Schnapsen 的结论。

事件流必须包含：相对行动方、领出和跟牌、报婚、换将、相对赢家、自己的新抽牌（只对自己可见）、阶段变化，以及 episode 边界。仅把现有 180 维按“轮到我时”喂给 GRU 可能漏掉两次决策之间的细节，尤其不能借用对手视角观察来更新本方 hidden state。不要使用未来完整轨迹反向构造当前记忆。

模型的当前快照为 180 维，记忆为 64 维；如果采用显式拼接，决策输入总宽度为 244。输入宽度不随历史长度增加。每张牌可能在哪个区域的组合不做 one-hot：单纯五张手牌就有 `C(20,5)=15,504` 种，若再乘对手手牌与牌堆顺序会迅速失控。120 维区域结构使用各牌的组合式编码，避开组合枚举。

必须同步改变训练数据组织：PPO 需要按玩家/episode 保存序列和边界，进行带 burn-in 的序列 minibatch；不能像现在 MLP 版本一样任意打散单步样本后重建 hidden state。NFSP 的 SL reservoir 也需定义可复现的历史上下文/序列采样，避免把只保存单步 hidden state 的陈旧表征当作充分信息。完整历史可变长存储，GRU 状态固定宽度；固定维度不等于完美记忆或精确信念状态。

如果暂时不准备承担递归训练复杂度，**先做 290 维 MLP 消融更稳妥**。不要为追求更低维直接上线丢历史的 180 维 MLP。

## 候选方案与取舍

| 表征 | 优点 | 本项目取舍 |
| --- | --- | --- |
| 465 维 MLP | 已验证、检查点稳定、便于基线比较 | 保留为本次对照；不是维度爆炸，但冗余明显 |
| 290 维 MLP | 去掉动作列表等冗余，保留现有五条历史 | 推荐作为第一步实测迁移 |
| 180 快照 + GRU64 | 固定宽度，纳入完整可见事件历史 | 最推荐的目标方案；需序列训练和隐藏信息测试 |
| 20×共享 card embedding + pooling | 可扩展更大牌组，参数共享 | 20 张牌并不需要复杂 embedding；简单池化可能丢掉牌之间的区域关联 |
| Transformer 全历史 | 表达能力强、可关注远距离事件 | 对本项目训练预算增加实现和调参成本，未证明优于小 GRU |
| 精确对手手牌 belief | 若正确维护可表达完整不确定性 | 全组合 posterior 昂贵；逐牌边缘概率虽小却不能表达牌间负相关，不能自称精确 belief |

花色对称性可以后续处理：先采用完整花色置换的数据增强，观测、历史、合法 mask 和动作索引必须同步变换并可逆。固定将牌到标准花色也可以，但其余花色排序需要一致规则。当前原生卡牌花色顺序 H/C/S/D，历史动作索引 H/S/C/D；混淆这两个顺序会产生合法但语义错误的训练数据，应加入全 28 动作的往返测试。

465→180 可使第一层 `input→256` 的权重从 119,040 降至 46,080，减少 61.3%；465→290 为 74,240，减少 37.6%。这是第一层而非整个网络的节省，加入 GRU 后参数和计算会增加。经验池更值得关注：默认两名 NFSP 玩家 RL 各 100k、SL 各 200k，仅 float32 state/next_state 字段合计约 **1.488 GB（十进制）**，尚未计入 mask、动作、概率和索引。类别/二元特征可按 uint8 存储、取样时转换；这样减少存储不改变模型语义，但不在本次算法对比中同时修改。

## 如何证明推荐真的更适合

按同一训练预算、至少 5 个预先固定种子，对 465 MLP、290 MLP、180 MLP（刻意丢历史的消融）、180+GRU64 做对比。报告对随机/规则/冻结强策略的胜率和游戏点差、配对种子置信区间、达到预设胜率所需决策数/时间、峰值内存，以及熵、KL、解释方差和梯度异常。最好另做近似参数匹配的模型对照，分离容量和信息来源的作用。

逐步启用完整跟牌历史、换将事件、自己抽牌记忆，检查究竟哪种信息带来收益。第二阶段适合加入只使用规则允许信息的精确小残局求解器作为参考；第一阶段用特权真实手牌搜索会导致无效评估。

上线 v3 前必须有：隐藏牌置换不影响当时观测；合法 mask 与动作还原一致；事件只更新正确玩家的记忆；episode 重置不串局；续训恢复 hidden/序列边界；同牌组换座位评估一致。表征可降低冗余和信息损失，但无法单独保证自博弈收敛；高熵、学习率、对手非平稳性和奖励目标仍需分别诊断。
