# 学习曲线、平台期与训练预算

## 推荐运行

项目自带虚拟环境。正式比较优先使用固定预算的 `compare`，四种算法都跑完相同训练局数；平台期诊断不会提前终止任何算法。

```powershell
$out = "runs/academic_$(Get-Date -Format yyyyMMdd_HHmmss)"
.venv/Scripts/python.exe -m nfsp compare `
  --algorithms he-ppo,ppo,nfsp,dqn --baselines random,heuristic `
  --seeds 42,43,44 --games 100000 --eval-every 5000 `
  --eval-games 2000 --test-games 4000 `
  --device cpu --num-envs 256 --workers 1 --torch-threads 4 `
  --plateau-window 5 --plateau-delta 0.02 --plateau-min-rounds 10 `
  --output $out
Invoke-Item "$out/report.html"
```

另一 PowerShell 窗口可在运行期间打开输出目录的 `live.html`。不需要 HTTP 服务、额外软件或网络。页面每 10 秒刷新，数据在完成一个评估检查点后更新；结束后停止自动刷新。中断时保留最后页面，不应仅凭页面“运行中”判定进程仍存活。

`experiment.py` 同样自动生成三种学习曲线、统计文件和实时页面。它比较 adaptive-ppo（自适应学习率和熵）与标准 PPO，且会验证集早停；`compare` 中 he-ppo 仅自适应熵，学习率固定。两套主算法定义不同，不能直接合并其结果。若用一键入口研究完整 20 轮轨迹，可以设 `--rounds 20 --min-rounds 20`；最大决策数限制仍独立生效。

## 训练多少轮

本项目中“轮”指一次评估间隔，不是 PPO epoch，也不是单次梯度更新。

| 用途 | 训练局数/算法/种子 | 每隔多少局评估 | 评估轮数 | 训练种子 | 每对手评估/最终测试局数 |
| --- | ---: | ---: | ---: | --- | --- |
| 流程检查 | 2,000 | 500 | 4 | 1 | 128 / 256 |
| 初步研究比较 | 100,000 | 5,000 | 20 | 42,43,44 | 2,000 / 4,000 |
| 扩大预算的正式研究起点 | 500,000 | 10,000 | 50 | 42,43,44,45,46 | 4,000 / 10,000 |

这些是可执行的起始预算，不是收敛所需轮数的保证。PPO 每个 wave 内仍默认最多 4 个优化 epochs，无需把 epochs 改成 20 或 50。先用 20 轮观察训练速度、种子波动和平台期诊断；如果目标是更充分地比较 NFSP/DQN 与 PPO 的长期表现，可预先安排 50 轮、5 个种子的独立新实验。不能根据最终测试结果反复调整训练轮数后，仍把同一批测试数据称为未见数据。

四算法 × 三种子 × 100,000 局 = 1,200,000 训练局，另有第 0 轮及 20 个训练后评估点。`--eval-games` / `--test-games` 是每个策略对每个对手的总对局数，必须为偶数以交换座位。NFSP/DQN 两个玩家策略分别评估后在种子内等权平均，评估总工作量相应更多。更大正式实验为 10,000,000 训练局，耗时需从本机初步运行估算。

硬件时间受本机负载影响；本次开发验证期间可能有测试、浏览器和其他进程竞争资源，时间曲线不能当作隔离硬件基准。固定游戏预算不是严格相同决策预算或相同计算预算。决策数与时间曲线提供额外比较视角，时间轴不等于重新做了一次等时间训练实验。

## 三种横轴和误差带

- `games`：共同实测训练局数检查点，横向比较样本量。
- `decisions`：累计环境动作数。不同算法和不同种子每局长度不同，先在每个种子的轨迹内线性插值，再在相同动作数聚合。
- `seconds`：累计纯训练秒数，排除评估、报告写入和检查点 I/O。同样先逐种子插值，再聚合；不能把各个种子的时间先平均后当成等时间测量。

每条算法曲线只使用该算法全部已纳入种子共同覆盖的区间，不外推，不在尾部悄悄减少种子数。不同算法的可用横轴范围可能不同。早停导致后段没有完整种子时，均值曲线到共同覆盖边界结束。旧一键实验 JSON 没有决策计数时，跳过决策图，不从局数推算伪造动作数。

粗线是跨种子均值，细线/小点保留未平滑的实测种子轨迹，阴影是逐点 95% Student-t 区间。只有一个种子时不生成误差带。少量种子的 t 区间依赖分布假设并可能不稳定；阴影不是整条曲线同时覆盖的置信带，也不是数千副评估牌组的区间。插值用于展示，平台期判断只用实测共同检查点。

实时报告只显示已出现的种子，种子数会随着实验进行变化，不能把中途曲线作为最终汇总结果。

## 预先定义的平台期判断

训练前将规则写入 `protocol.json` 的 `learning_analysis`：

1. 每种算法、每个固定 baseline 独立分析，至少有 3 个独立训练种子。
2. 至少完成 `--plateau-min-rounds` 个共同评估间隔，默认 10。
3. 取末尾 `--plateau-window` 个共同检查点，默认 5。20 轮、每轮 5,000 局时，是 80,000–100,000 局的窗口，跨度为 4 个评估间隔。
4. 每个种子计算窗口内最高与最低胜率之差，必须不超过 `--plateau-delta`，默认 0.02，即 2 个百分点。
5. 每个种子计算后半窗与前半窗胜率均值之差；5 点窗口分别取末 2 点和前 2 点，中间点只用于极差检查。跨种子变化的 95% t 区间必须完全处于 ±2 个百分点之内。

输出三种状态：数据不足、当前窗口观察到平台期、未确立平台期。变化不显著或区间跨越 0 不足以认定平台期；噪声、振荡、上升和下降都可能导致“未确立”。规则不触发早停，不选择最终模型，也不是带统计保证的顺序检验或纳什收敛证明。即使对随机策略的平台期成立，对规则策略仍可能继续变化。

## 评估与测试隔离

`compare` 每个检查点使用独立于训练的评估 seed，不同检查点使用不同 seed；算法之间共用相同牌组以便对照。最后预算末尾策略再用独立最终测试 seed 评估，算法汇总与 HE-PPO−PPO 配对差来自这些最终测试，不从学习曲线中挑最好的一点。交叉对战另有独立 seed。三个流的种子记录在协议中。

`experiment.py` 保留原有机制：固定验证牌组绘制学习曲线和选择 `best.pt`，独立最终测试只评估所选策略。新平台期分析不改变其既有早停条件。

## 产物与复现

- `live.html`：运行中离线刷新页面。
- `report.html`：最终综合报告及平台期表格。
- `figures/learning_<编号>_<games|decisions|seconds>.svg`：可单独导入论文/幻灯片的矢量图；编号按 baseline 名称排序，图中标题注明对手。
- `learning_statistics.csv/json`：每个轴上的均值、种子数、标准差与区间；插值点和原始点由原始 `curves` 数据区分。
- `plateau.json`：规则和每种算法/对手的窗口、逐种子变化/极差与结论。
- `results.json`：保留原始评估、最终独立测试、交叉对战、训练计数和完整协议。
- `events.jsonl`：训练与评估过程记录；无需等训练结束才有数据。
- `compare` 的各算法/种子目录：`policy_0.pt`、每次评估点的轻量 `policy_<局数>.pt`，以及最终 `policy.pt` 与完整 `latest.pt`。

实验输出目录必须为空，避免混合不同运行。调度器仍不支持整套实验的中断续跑；已有完整快照可通过各算法训练入口单独恢复。

已有一键实验可以用 `experiment.py --render-only 路径/results.json` 重绘。对比实验可以通过 Python 调用 `nfsp.experiments.render_comparison(output, data)` 重绘；旧结果的最终测试口径仍以原协议为准，重绘不会补做测试。

方法参考：[Empirical Design in Reinforcement Learning (JMLR, 2024)](https://jmlr.org/papers/v25/23-0183.html)。本项目的 5 点/2 个百分点平台期阈值属于预先指定的工程分析规则，不是该论文给出的通用收敛阈值。

## 论文用白底图（可选）

内置报告无需绘图库。另提供 Matplotlib 导出器，复用已保存的统计量，生成白底、色盲友好配色的三联图，分别保存 SVG、PDF 和 300 DPI PNG。本机系统 `python` 已装 Matplotlib，项目 `.venv` 未装，因此本机运行：

```powershell
python scripts/export_learning_figures.py runs/academic_comparison_20260910/results.json
```

其他环境使用装有 Matplotlib 的 Python；如希望用项目解释器，可先在该环境安装 Matplotlib。这是可选绘图依赖，不影响训练和离线 HTML。默认输出 `publication_figures/`，`manifest.json` 记录来源、baseline 编号和绘图库版本。
